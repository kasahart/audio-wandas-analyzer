# 手動確認の手順

CI では確かめられない次の4つを、人が操作して確かめるための手順です。

1. 実際の音声出力
2. 校正
3. レシピ
4. Windows 実機での日本語ファイル名

確認用の音声はすべて合成音で、期待する値が決まっています。所要時間は全部で 40 分ほどです。

## 0. 準備

### 拡張を入れる

最新の main から作った VSIX を使います。手元でビルドする場合は次を実行します。

```bash
npm ci
npm run package:vsix
```

VS Code の拡張機能ビューで **…** → **VSIX からのインストール…** を選び、`audio-wandas-analyzer-*.vsix` を指定します。Marketplace 版が入っていても上書きされます。インストール後に **ウィンドウの再読み込み** をしてください。

日本語の表示を確かめるため、VS Code の表示言語は日本語にしておきます（**Configure Display Language** → `ja`）。

### Python 環境

README のクイックスタートのとおり、仮想環境を作って依存を入れます。コマンドパレットの **Audio Analyzer: Python 環境を選択** で、その仮想環境を選びます。

### 確認用ファイルを作る

その仮想環境の Python で次を実行すると、`manual-check-files/` に確認用ファイルができます。出力先は引数で変えられます。

```bash
python scripts/make-manual-check-files.py
```

Windows の確認では、出力先を日本語を含むパスにすると、パスの扱いも一緒に確かめられます（例: `C:\Users\<名前>\デスクトップ\確認用 音声`）。

| ファイル | 中身 | 使う節 |
| --- | --- | --- |
| `01_校正_1kHz_RMS0.1FS.wav` | 1 kHz、RMS 0.1 FS、10 秒、モノラル | 2 |
| `02_校正_2ch_ch1は0.1FS_ch2は0.01FS.wav` | 1 kHz。ch1 は RMS 0.1 FS、ch2 は 0.01 FS | 2 |
| `03_再生_左→右→両方.wav` | 0〜2 秒は左だけ 440 Hz、2〜4 秒は右だけ 880 Hz、4〜6 秒は両方 660 Hz | 1 |
| `04_再生_毎秒ビープ_0秒400Hzから100Hzずつ上がる.wav` | 毎秒 0.2 秒のビープ。0 秒は 400 Hz で、1 秒ごとに 100 Hz ずつ高くなる | 1 |
| `04b_形式違い/毎秒ビープ.flac / .ogg / .mp3` | 04 と同じ中身の FLAC・OGG・MP3 | 1 |
| `05_比較_A_基準.wav` | 白色雑音 | 3、4 |
| `05_比較_B_100ms遅れ_半分の振幅.wav` | A を 100 ms 遅らせ、振幅を半分にしたもの | 3 |
| `05_比較_C_同期_半分の振幅.wav` | A の振幅を半分にしたもの（遅れなし） | 4 |
| `06_エラー確認_短すぎる_1000サンプル.wav` | 1000 サンプル（約 21 ms） | 4 |
| `07_エラー確認_壊れたファイル.wav` | 中身が壊れた WAV | 4 |
| `08_日本語ファイル名/…/` | 全角スペース、半角カナ、丸数字、絵文字などを含む名前の 7 ファイル | 5 |
| `09_CSV_振動_80Hz_RMS1.csv` | 1 列目が時刻の CSV。80 Hz、RMS 1.0 | 2 |

問題があったときは、**出力** パネルの **Audio Wandas Analyzer** のログとスクリーンショットを添えて Issue にしてください。

## 1. 音声出力

`03`、`04`、`04b` の各ファイルをパネルに開いて確かめます。

- [ ] `03` を ▶ で再生すると、左から 440 Hz、次に右から 880 Hz、最後に両方から 660 Hz が聞こえる。左右が逆なら不具合
- [ ] 波形をクリックしてから `Space` を1回押すと再生が始まり、再生中はカーソルが進む（もう1回押すと一時停止。始まりは 0.1 秒のフェードインなので、押したら 1 秒ほど待つ）。`F` で再生位置にカーソルが追従する
- [ ] `04` で 3〜5 秒をドラッグしてループにすると、700 Hz・800 Hz のビープだけが繰り返し聞こえる。「🔁 ループ再生中」が出る
- [ ] ループをクリックで解除すると、最後まで通して再生される
- [ ] `03` と `04` を両方トラックにし、`03` の再生中に `04` の ▶ を押すと、再生が `04` に切り替わる（同時に鳴らすのは 1 トラックだけで、聞き比べ用の仕様）
- [ ] `04b` の FLAC・OGG・MP3 も、WAV と同じ高さのビープが同じ時刻に鳴る
- [ ] `04` でループを作り **WAV** で書き出すと、書き出したファイルにはループ区間（700 Hz・800 Hz）だけが入っている

## 2. 校正

数値は、フォルダを開いたときの表の **Leq dB(A)** 列で確かめます。1 kHz は A 特性の補正がほぼ 0 dB なので、RMS からそのまま計算した値になります。

- [ ] `01` を含むフォルダを開くと、未校正の `01` の Leq は **−20.0**
- [ ] `01` のトラックの **校正**（または **Audio Analyzer: 校正値を設定**）で、次のように入力する。Leq が **94.0** になる（1 Pa = 94 dB SPL）
  - モード: 校正済みの物理量
  - 係数: `10`
  - 単位: `Pa`
  - 基準値: `0.00002`（既定値のまま）
- [ ] 校正した後、波形・スペクトルの縦軸が Pa や dB SPL の表示に変わる
- [ ] VS Code を再起動して同じワークスペースで `01` を開き直しても、校正が残っている
- [ ] `02` は未校正で ch1 が −20.0、ch2 が −40.0。ch1 に係数 10、ch2 に係数 100（どちらも Pa）を入れると、両方 94.0 になる
- [ ] `02` の片方のチャンネルだけを Pa、もう片方を `m/s^2` にすると、表の Leq は **—** になり、表の上に「読めない 1」が出る。それを押すと、`02` の行に「Selected channels have different units; scan them separately」（英文）と出る。落ちたり、混ざった値が出たりしない
- [ ] **すべてのチャンネルをフルスケールに戻す** で、Leq が −20.0 / −40.0 に戻る
- [ ] `09` の CSV をトラックとして開くと（エクスプローラーで右クリック → **Audio Analyzer で解析**）、カーソル位置のスペクトルで 80 Hz にピークが出る。係数 1、単位 `m/s^2`、基準値 1 を入れると、単位が m/s² の表示になる。CSV はフォルダの表には意図的に並ばない（メタデータ扱い）ので、表の Leq は確認対象外

## 3. 比較とオフセット

- [ ] `05_A` と `05_B` をトラックにすると、B の波形が 100 ms 遅れて見える
- [ ] B のオフセット値をクリックして `-100` を入力すると、A と B の波形の山がそろう。ダブルクリックで 0 に戻る
- [ ] オフセット −100 ms のまま A を基準にすると、下のパネルの伝達関数がほぼ平らな **−6.0 dB**、コヒーレンスがほぼ **1** になる
- [ ] オフセットを 0 に戻すと、コヒーレンスが大きく下がる（ずれを正しく反映している）

## 4. レシピ

- [ ] トラックを 1 本以上比較台に出し、**書き出し → レシピを開く…** で同梱の **filter-welch**（`python-backend/recipes/`）を開くと、手順バーがそのレシピの手順になり、最後の手順のスペクトル（1 kHz にピーク）が比較台に出る
- [ ] `05_A` を基準スロット、`05_C` を比較 1 にして **transfer-function** を開くと、手順バーは「get_channel → transfer_function」の 2 手順になり、伝達関数がほぼ平らな **−6.0 dB** になる
- [ ] 同じ組み合わせで **coherence** を開くと、ほぼ 1 になる
- [ ] 3 節の状態（A を基準、B のオフセット −100 ms）で **書き出し → レシピとして保存** した `.recipe.json` は wandas の `RecipePlan.load()` で読める
- [ ] 入力が 3 つ以上のレシピや wandas のレシピでない JSON を開くと、開けない理由が状態表示に出て、手順バーは変わらない

## 5. Windows 実機での日本語ファイル名

Windows で、確認用ファイルを日本語を含むパスに置いて確かめます。可能なら Windows のユーザー名や仮想環境のパスにも日本語が入った状態で試してください。

- [ ] `08_日本語ファイル名` フォルダを右クリック → **Audio Analyzer で解析** で開くと、表に 7 ファイルが文字化けせずに並ぶ（全角スペース、半角カナ、①、㈱、【】、～、絵文字、ü・ñ）
- [ ] どのファイルも ☐ → ☑ でトラックにでき、波形とスペクトログラムが出て、再生できる
- [ ] ファイル名が長いものは、名前の中央が省略されて末尾が残り、ツールチップでフルパスが見える
- [ ] **表・ソ・能・予** のファイル（Shift_JIS で問題になりやすい字）が、ほかと同じように開ける
- [ ] 日本語のファイルを校正し、VS Code を再起動しても校正が残っている
- [ ] PNG・CSV・WAV・レポートを、日本語のフォルダに書き出せる。出力したファイル名と、レポート内のファイル名が文字化けしていない
- [ ] **出力** パネルの **Audio Wandas Analyzer** のログで、日本語のパスが文字化けしていない
- [ ] `08_日本語ファイル名` の 7 ファイルに `01` を加えた 8 ファイル以上を開いたり閉じたりを繰り返しても、「exited unexpectedly」や EPIPE のエラーが出ない
