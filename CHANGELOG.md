# Changelog

User-visible changes per release. Pull requests add a line under **Unreleased**; the release PR turns it into the version heading (the tag `vX.Y.Z` must match `package.json`).

## Unreleased

- Entry and Compare: the held plot (a slot key held down) and Compare's Δ pane now read the pointer like every other plot. The point nearest the pointer is marked, and its readout appears in the plot's own row just above it: the held plot's title row, and the Δ pane's headline row instead of the controls row over the overlaid plot (#670).
- Cursor spectrum: with no line to draw, "no data" is shown in the middle of the plot by the shared plot component, as every other plot says why it is empty. Every UI smoke test now fails on a plot on screen that the shared plot component did not draw (unless it is on the list of plots still waiting to move), and one test gives every plot the same gestures (#668).
- Compare: the row above the plots shows the pointer's readout on its right, as the cursor spectrum's header does, instead of the largest difference ("Compare 1 − base · 100 Hz base … / compare …"), which read like a readout of the cursor. The row keeps its notes (choose a role, steps bypassed, the region, a trigger's event counts). Compare's readout is no longer in the toolbar, and the backend no longer computes the largest difference that row used to name (#664).
- Compare: the readout of a hover on a step's plots (name / where / value) is shown in the toolbar's readout row, as the track lanes' is, instead of in a box over the plot that hid the lines around the point being read. Every plot's readout now has a row outside the plots, and every UI smoke test fails if a readout is shown over a plot (#662).
- Track view: the readout of a waveform lane's hover (recording / time / amplitude) is shown in the toolbar beside the cursor time, in the lane's colour, instead of in a box over the lane that hid the waveform around the point being read. Its room in the toolbar is kept while it is empty, so a hover never wraps the toolbar and moves the lanes, and a long recording name is cut short before the time and amplitude are (#656).
- Compare: in a step's ⚙, Enter applies the form only from one of its fields. On a button such as Remove it now presses that button instead of applying the form (#658).
- Compare: a step's ⚙ offers every parameter wandas describes for it, at wandas' default, instead of "No settings known for this step" for most operations. sound_level gets its frequency weighting (A, C, Z or none), time weighting and dB; loudness, sharpness, roughness, normalize, power, cepstrum, coherence, CSD and transfer function get theirs, and welch and stft their hop, window length and averaging. A number wandas picks itself reads "auto" while empty. A form of more than four fields folds the rest behind "n more"; a changed value stays out and its name is bold. Only changed values are written into the Recipe, and a value wandas refuses is marked on its chip with wandas' reason. An operation without parameters says "No settings". A level step set to dB is drawn as its dB values (#654).
- Track view: the pointer on a waveform lane now reads the waveform as Compare and the cursor spectrum do. It reads the point nearest the pointer within 20 px (a narrow peak beside the pointer at its top), and shows a cursor, a level line in the lane's colour, and a readout of the recording, the time and the amplitude. Before, it showed a time line only. The other lanes and the spectrograms still show the time line, and the click cursor and analysis window are unchanged (#652).
- Compare, cursor spectrum and pair plot: the cursor reads the point nearest the pointer, measured across and up within 20 px. A narrow peak a few pixels beside the pointer is now read at its top instead of at its skirt under the pointer. With no point that near, the cursor reads the point under the pointer, as before. Arrow keys still step one bin. The cursor spectrum and the pair plot follow each other at the frequency that was read (#650).
- Compare: a trigger added right after the input (before the chain's high-pass and slice) draws its events over the whole file, instead of failing on every recording with "Recipe output is ChannelFrameSegments, not a Frame" (#648).
- Compare: a trigger's events plot keeps its height above the tracks instead of covering the top of the base lane (by 24% at 1600×1000, and half the lane on a short window); the tracks scroll below it (#646).
- Cursor spectrum: the level axis is named as in Compare, in the UI's language and saying when the files are uncalibrated ("Amplitude, uncalibrated [dBFS]"), instead of the backend's "Spectrum amplitude level" or "Band level". A panel too short for the name keeps the unit on its axis, and the header now has a legend with the full level name and each line's colour and name. With two level axes the legend groups the lines by side, as before (#642).
- Compare, track view and cursor spectrum: each recording without a role has a colour of its own (teal, brown, olive, sand) in every view, so its peaks can be followed from line to line. Compare drew all of them grey before. The colour is kept when other recordings change role or new recordings are added (#644). With two level axes, a line read on the right-hand one is dashed, like its swatch in the legend. The analysis window band under the cursor is a neutral grey instead of amber, which read as a failed step's orange (#640).
- Compare: in the steps view, a two-channel recording is one lane holding its step's picture. Before, a blank second-channel lane took half the track's height, and the first lane's header named "ch1" above a picture of the compared channel (#638).
- Compare: the value axis names what a step made of the sound: RMS after rms_trend (not "Value"), time-weighted RMS after sound_level, and power in the unit squared after power (not "Amplitude"). Like the level axis, an amplitude axis now says it is uncalibrated while the files are (#636).
- Compare: a heatmap (STFT, roughness over frequency, cepstrogram, their difference) has a colour bar that names what its colour measures, with unit and reference, and shows both ends of the scale, instead of a bare span such as `±0.079` in the corner (#634).
- Compare: after a metric step (rms_trend, loudness, roughness, sharpness), the step bar judges the steps that follow at the metric's series rate (rms_trend's is the recording's over its hop; loudness and sharpness 500 Hz; roughness 10 Hz). A filter cutoff above that Nyquist, or an FFT longer than the series, is marked orange with its limit, not left to fail with wandas' English error. HPSS, which crashes the backend on a short series, is greyed out in ＋ there, and so is fft after roughness, whose result cannot be drawn (#632).
- Compare: the input chip draws a multi-channel recording as the channel it is compared as, like every step after it, instead of the mean of its channels under a legend that named one channel; a recording without a role is drawn as the channel its legend names (#628).
- Cursor spectrum: drawn by the same plot code as Compare's panes, so the same spectrum looks the same in both: plain tick numbers with the units in the axes' names, the frequency axis' name at the right end of its ticks, and 1/3-octave bands as one step per band instead of a joined staircase. The second level axis' values sit at the left axis' gridlines. Zoom, the dB range, box drag and the arrow-key readout work as before. In both places a line past the dB axis now leaves the plot where it crosses the axis instead of running along its edge, and a log frequency axis zoomed between two of its ticks labels its ends (#622).
- Cursor spectrum: a long FFT row is thinned out as each log-spaced stretch's lowest and highest bin, each at its own frequency, as Compare draws a level spectrum, instead of the stretch's highest bin only. A tone keeps its level; noise between tones now shows its spread rather than only its upper edge, so the same recording looks the same in both places. A zoom still draws every bin (#618).
- Recipes: **Export → Open recipe…** opens a wandas `.recipe.json` in the Compare step bar, where its chain runs on each compared recording and every step is drawn like a chain built with ＋. A two-input recipe that pairs a reference channel with a response channel (the bundled transfer-function and coherence) opens as one chain whose cross-channel step pairs with the base slot. The separate recipe result panel, the VS Code command **Run wandas recipe** and the backend's `run-recipe` command are gone (#616).
- Report: the figures' spectra, the base group's median and Δ are taken from every Welch bin and only then decimated to be drawn, as in Compare, so a narrow difference reads the same in the report as on screen. 報告に scans the report's files for every bin first (a stored result keeps the 192 points alone). The entry table's 192-point spectrum, the 1/3-octave Δ and the CSV are unchanged (#610).
- Cursor spectrum and pair plot: the frequency axis is named ("Frequency [Hz]" / "周波数 [Hz]") under its ticks, as the level axis is (#611).
- Compare: overlaid recordings are drawn loudest first and quietest last, on top, by their level over the part shown (a waveform as drawn on the shared amplitude axis, a spectrum's bins), so a louder recording no longer covers a quieter one; zooming or panning re-orders them. Colours and the legend stay as they are (#557).
- Compare: a level or gain spectrum is drawn as each stretch's lowest and highest bin, before a zoom and after it, about one stretch per two pixels: a tone keeps its height at every zoom, instead of a band mean that lowered narrow peaks the wider the view was. Noise with many more bins than pixels (an `fft` over the whole file) shows as a band, as the undecimated line would (#607).
- Compare: a base group's median, the "show difference" line, the headline's largest difference and a held step's "without − with" are now taken from every bin, sample and column of the Frames, and only the result is thinned out for drawing. They were taken from each recording's drawn points (192 log bands, 400 blocks, min/max buckets), so a narrow difference was averaged away and the median depended on how each picture was drawn. A difference line is drawn as each stretch's smallest and largest value, so its peaks stay. A level over time is still compared block by block, each block measured from all its samples (#605).
- Cursor spectrum: when the visible tracks use two level references (a Pa track and an uncalibrated one, say), the second is read on its own level axis at the right instead of hiding the panel; a legend in the panel's header shows which lines are read on which side and with two axes the cursor readout names the reference ("-17.0 dB re 1 V") and its level guide runs only to the line's own axis. Three or more references still show the warning (#603).
- Tracks: the spectrogram's colour bar shows its end values (0, -60) and its unit with the reference ("dB SPL re 20 µPa") once along the bar, so no label is cut at the right edge; on a lane too short for the reference it reads the unit alone ("dB SPL") (#601).
- Tracks: the small power spectrum at the right of each track row is gone; the waveform and spectrogram take its width. The cursor spectrum panel at the bottom (folded until opened from its header) shows every track's spectrum, as before (#589).
- Tracks: the 🔊 mute button is gone from the track header. One track plays at a time, so muting it only silenced the track you had just chosen to play (#591).
- Tracks: the spectrogram's auto colour scale ends on round dB values (-120…-23.21 dB now reads -120…-20): each end is widened outward to the coarsest 1, 2 or 5 × 10ⁿ step that moves neither end by more than 8% of the range shown. The cursor spectrum's auto dB axis does the same; values typed in the range popover or ⚙ stay as typed (#595).
- Compare: after a cepstrum or a cepstrogram, ＋ now adds wandas' lifter (it was greyed out for lack of a cutoff field). A new lifter keeps the quefrencies below 2 ms (cutoff 0.002 s, low); its cutoff in seconds and its side (low: below the cutoff, high: above it) are set in ⚙, and the result is drawn as the cepstrum it came from (#587).
- Compare: a cepstrum is drawn as each stretch's minimum and maximum, as a waveform is, instead of a jagged zigzag through alternate peaks (#583).
- Tracks: after a cursor click or a stop, every track's analysis window band moves in the same frame once all their cursor spectra have arrived (at most 1 s later), instead of reappearing track by track from the top (#598).

## 0.0.15

- Compare: with a trigger's events overlaid, the tracks stay under them, each recording as the trigger takes it, with the trigger level as a dashed line, where each event was cut shaded and a mark per event: ▶ plays the event, × leaves it out (↺ puts it back). Each track counts the events used (#567).
- Compare: a click on a trigger's event line leaves that event of that recording out (it stays faint; another click or ↶ puts it back). The steps after the trigger that take the events together, such as their mean, run without it (`wandas.segments.drop`). Changing the trigger, a step before it or the region brings the events back, with a notice. The readout says where in the recording each event was cut (#567).
- Compare: a level trigger from ＋ (トリガー) cuts every event where a channel crosses a level; it starts at half the tracks' peak, and its channel, level, length and pre-trigger are set in ⚙. The comparison draws every event of each recording over the time from its trigger, in the recording's colour, and the headline counts them. After it, ＋ offers the events' mean, transfer function and coherence. A level nothing crosses says so (lower it in ⚙) and counts 0; a chain that ends with the events is compared but not exported for many files (a Recipe runs to their mean, transfer function or coherence). Needs wandas 0.13.0, which records these steps in the Recipe (#567).
- Compare: a step that cannot run on the recordings now says why instead of an empty plot. ＋ greys `noct_synthesis` out on recordings that are not 48 kHz (wandas runs it at 48 kHz only) and points to `noct_spectrum` for octave bands; a step that fails on a file is marked ⚠ with wandas' reason, and the plot's message wraps to its width on a narrow screen (#568).
- Compare: the step bar's name is now a recipe button ("Recipe: Overall spectrum ▾"). Its menu starts the steps from a preset chosen by purpose: overall spectrum, band levels (A-weighted), time and frequency (spectrogram), level over time, loudness and roughness. The chain is replaced as one edit ↶ takes back, the region stays, the last step is shown, and the chain is edited as before; once changed the button reads "(edited)". Loudness, sharpness, roughness and `rms_trend` steps are drawn as their own values with their unit (sone, acum, asper, dB) on recordings of any length; on a long one they were drawn as a level in dB of those values. The table's Leq(A) is no longer A-weighted twice when the chain has an A-weighting step (#565).
- After pausing playback, every track's analysis window band and cursor spectrum follow the cursor to where playback stopped; they used to stay at a different mid-play time on each track (#559).
- VS Code calibration picker: its wording comes from wandas' unit and level label for the file as read — "Uncalibrated full scale (FS / dBFS)" for audio, "Uncalibrated raw input units (dB re 1 input unit)" for a CSV — and a calibrated channel names its reference with wandas' label from the analysis ("factor 2; Pa; dB SPL re 20 µPa") instead of a label rebuilt from what was typed (#562).
- Tracks: a role set on a track's header chip now repaints its cursor spectrum in the role colour right away; it kept the track's own colour until the next repaint (#561).
- Level labels come from wandas' own reference for each channel: the dataset table's Leq and band values read "[dB SPL re 20 µPa]" for audio calibrated to Pa (they always said "[dBFS]"), "[dBFS]" while uncalibrated and plain "[dB]" when the recordings' references differ; the steps view names its level axis by the channel drawn, so a file calibrated on ch1 only reads "Amplitude [dB SPL re 20 µPa]" with ch1 drawn; the entry overview's colour scale follows suit. Uncalibrated is told by the calibration status, not by an FS unit, and a CSV is told from audio by wandas' unit instead of its file extension. The folder's stored results are computed once again (#556).
- Uncalibrated CSV tracks are labelled in raw input units instead of full scale: the level axis reads "Amplitude, uncalibrated [dB re 1 input unit]", the calibration badge reads RAW, the calibration picker offers "Raw input units (dB re 1 input unit)", and the summary picture's hint, the entry overview's colour scale and a time signal's axis follow suit; audio files keep FS / dBFS (#544).
- VS Code: when no Python interpreter is found, the warning offers "Try Browser Version", which opens the browser version so you can try the analyzer without Python (#546).
- Compare opened from the tracks with no role at all starts with the first two recordings as base and compare 1 (compare 1 alone when rows are grouped, the group median being the base); the legend's chips change them (#540).
- Recipes: a psychoacoustic Recipe (`roughness`, `roughness-heatmap`, and `loudness` on a file of a few samples) run on a file too short for it — for roughness, shorter than its 200 ms window (9600 samples at 48 kHz) — now says the settings don't fit this file, like the other Recipes, instead of "This request could not be processed." (#525).
- CSV tracks no longer show the CLIP badge: their values are physical (Pa, m/s², V…) with no full scale, so the report's Raw Peak and Clipped columns read "—" for them instead of "Yes"/"No" (#524).
- Compare legend: each recording's chip names its role ("Base ▾", "Compare 1 ▾"), or offers "Role ▾" outlined when it has none (#538).
- Web: the empty view offers "Try with samples": three short synthetic recordings (a hum, with a whine, with clicks) load on a click, to try the app without audio at hand (#536).
- Help: a "? Help" button in the footer opens it in every view; it starts with the app's flow in three lines. The Web version's Python boot card no longer covers the empty view's prompt (#533).
- Analysis chain: entry table for up to 100,000 recordings, a dataset table with distributions, a step bar that builds a wandas Recipe, and per-folder sessions (#410, #414, #415).
- Compare view: roles per recording, the tracks' selection carried in as the region, recordings drawn as they are computed, cross-correlation (#452–#456, #468, #472).
- Track lanes: waveform over spectrogram on one time axis, linked amplitude/colour/frequency scales, only lanes near the view drawn and fetched (#427, #442, #444).
- Cursor spectrum snaps to the nearest STFT frame; spectrogram cells centred on their windows (#436, #438).
- Cursor spectrum: tones show at their own frequency and level at every FFT length (it was averaged onto 192 even points, which read an 80 Hz tone at 94 Hz and up to 11 dB low); FFT lengths up to 2048 are drawn bin for bin, longer ones as up to 1025 log-spaced points holding each span's peak; the hover readout reads the loudest bin within a pixel of the pointer, and arrow keys still step one bin at a time; the CSV export writes every FFT bin (n_fft/2+1 rows at fs/n_fft spacing) and names any spectrum it had to leave out.
- Trackpad sideways swipe pans the timeline (#471).
- File table beside the tracks: the selected row's name stays readable (its tools show under the mouse, like other rows); the value column shows only when the table is maximized (#505).
- Track lanes fetch the waveform detail two screens either side of the view, so a pan no longer flashes the coarse overview, and a zoom out keeps the detail already fetched until the new one lands (#502).
- Entry table: the slot chips under the table are gone (roles show on the rows and the compare legend); the base group is chosen from a Base select beside Group (#504).
- Compare view: opens the first time on the input, the recordings as they are; after that on the step shown last, from the table or the tracks. On a waveform, a base group draws each of its recordings' waveforms under the compared one, with no level difference against the group's median, which is on no line (#518, #520).
- Step bar: shows the Recipe's steps only; the app's fixed "1/3 oct (table values)" chip after the chain is gone. The table's 1/3-octave values are listed under … with what the app computes outside the Recipe; for 1/3-octave bands on the compare view, add noct_spectrum from ＋. A base group too large to analyse unasked no longer stands in with the table's whole-file band levels: it has no line until Analyse is pressed (#523).
- Recipe results: a near-constant line (a flat transfer function, its phase) keeps a minimum y span (6 dB on dB axes, a full turn for phase, and only enough to hide floating-point rounding on other linear axes) instead of stretching rounding noise to full height; coherence is drawn on a fixed 0–1 axis.
- Folder: rows checked in the entry table show as tracks again on Windows and in folders opened through a link; the backend names each file as the extension asked for it, not as it resolves.
- Compare view: showing Δ no longer leaves the overlaid plot stretched from its old height, so hovered lines are no longer drawn twice (#503).
- Plots resized by the layout (the compare view's step bar expanded, the entry table's overview strip moved under it in a narrow window) are drawn again at their new size; ui-smoke fails any canvas left stretched (#552).
- Compare view: the ruler and the spectra it hides are no longer drawn on every resize or scroll; they are drawn again on leaving it (#554).
- Python backend answers requests for different recordings concurrently and reads audio straight into float32 (#462, #464).
- Updated to wandas 0.13.0 (#409, #446, #468, #567).
- Python starts only when a command, view or panel needs it; Select Python Environment can create a `.venv` and install the packages, detects PEP 668 interpreters and uses the Python extension's interpreter; Restricted Mode is supported with the user-level interpreter.
- Every analysis request can be cancelled and times out; Python's errors go to the "Audio Wandas Analyzer" output channel.
- A spectrogram or cursor spectrum that fails says why in its lane and is retried after a pause instead of on every frame; files larger than the cache are no longer re-read on every zoom; non-ASCII paths work on Windows code pages.
- Keyboard: one help (`?`) for every view; Compare toggles its base with `B` (was `0`); entry-table track marks are ☐/☑ (`T` toggles the focused row); canvases and resize edges are focusable and keyboard-resizable.
- Entry table keeps file names' ends in view with the full path as a tooltip; disabled controls say why; PNG/CSV export shows progress; settings popovers use plain labels; light-theme contrast and High Contrast Light role colours fixed; the transfer-function reference is called 参照 in Japanese.
- The webview may read, scan and export only files its panel lists; large folders are listed with a cap, skip symlinked folders and can be cancelled.
- The VSIX no longer ships scripts, tests, agent files or the debug WAV (about 10 MB → 4 MB).
- Requires VS Code 1.122 or later; only the latest VS Code release is supported.
- Tooling: CI runs verify on Linux, Windows and macOS; releases publish only after every CI job passes; pinned CI Python packages; Dependabot; type-aware ESLint and pyright in verify; wall-clock budgets only with `AWA_PERF=1`.
